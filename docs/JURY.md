# Как проверить решение

Все команды выполняются из корня репозитория. Нужны Python 3.10+, Docker с Compose и свободные порты 8080, 8000, 8001, 9201. Первый запуск скачивает зависимости и собирает образы; обучение не требуется.

## 1. Запустить исторический поток

Пять нужных CSV уже включены в `dataset/`. После клонирования репозитория достаточно скачать модель и запустить систему:

```bash
python3 tools/download_model.py
python3 tools/start_solution.py
```

Для Colima добавьте ко всем командам `tools/start_solution.py` `--context colima-mos-transport`. На Docker Desktop этот флаг не нужен. По завершении помощник проверяет веса, API, источник данных и первый цикл обработки; отчёт сохраняется в `artifacts/start-solution/report.json`.

Откройте [дашборд](http://127.0.0.1:8080/). В верхней панели архива нажмите **Продолжить**. Скорость можно увеличить. Поток идёт от выбранного времени до последнего доступного сообщения. **Сброс** возвращает архив к началу среза.

В `train` GPS берётся из `traffic.csv`, остановки и плановое время — из `schedule.csv`. Текущее отклонение вычисляется по обнаруженным прибытиям. `points.csv` для этого режима не нужен. В раздаче есть как реальные, так и синтетические траектории; этот просмотр не является независимой оценкой качества модели.

Для просмотра `validate` с выданным организаторами текущим отклонением:

```bash
python3 tools/start_solution.py --dataset-split validate --no-build
```

Этот режим использует включённые `dataset/validate/traffic.csv`, `schedule_plan.csv` и `points.csv`. Время CSV без часового пояса трактуется как UTC; на экране показано МСК. Это допущение можно изменить в настройках архива. Для собственного каталога раздачи добавьте `--data-dir /path/to/dataset`.

### Свой архив

Откройте **Параметры → Свой архив CSV**; форма доступна и из живого режима. Выберите `traffic.csv` с телеметрией, `schedule.csv` или `schedule_plan.csv` с расписанием и часовой пояс. При наличии можно добавить `points.csv` с готовым текущим отклонением. Формат столбцов — как в файлах раздачи; [контракт загрузки](OPERATIONS.md#собственный-исторический-архив).

Нажмите **Загрузить свой архив**, затем **Продолжить**. После проверки он появится третьим набором, **Свой архив**. Воспроизведение начинается с первой доступной телеметрии, по умолчанию со скоростью 10×; отклонение считается по GPS. Чтобы использовать загруженный `points.csv`, выберите источник **Готовое из points.csv** и загрузите срез снова.

Свой архив хранится до перезапуска backend. Встроенные train и validate остаются на месте. Общий JSON-запрос с CSV ограничен 80 МиБ; слишком большой или некорректный архив отклоняется с сообщением об ошибке.

## 2. Посмотреть результат

Выберите автобус на карте или в таблице. В карточке появятся прогноз задержки, целевая остановка и вероятность задержки больше двух минут, когда для неё достаточно данных. Под картой — предполагаемая причина с поясняющими факторами модели и ссылка на точный запрос/ответ ML.

Цвета: жёлтый — задержка от минуты, красный — более 2,5 минут, синий — опережение более 30 секунд. Прогноз рассчитывается при свежей телеметрии, известном текущем отклонении и остановке в плановом окне `(T+10, T+15]` минут.

В train вероятность помечена **приближённо**: калибровка перенесена с другого исторического набора. Неизвестная физическая причина не заменяется выдуманной пробкой. Факторы модели объясняют расчёт, но сами по себе не доказывают дорожную причину.

Справа от таблицы — очередь внимания и журнал предупреждений. Журнал можно скачать в JSON. В полном интерфейсе снизу доступны диагностика источника и состояние сервисов. Режим для диспетчера включается флагом `--ui-mode dispatcher`; при запуске с архивом он начинает воспроизведение сразу.

## 3. Подать NDTP из официального эмулятора

Только для этого сценария нужна отдельная полная раздача организаторов: папка `/path/to/dataset` с `train/` и файлом `ndtp-telemetry-emulator.tar`. Образ эмулятора в репозиторий не включён. Он рассчитан на `linux/amd64`; на Apple Silicon Docker должен поддерживать его запуск.

```bash
python3 tools/start_solution.py --data-dir /path/to/dataset --official-emulator
python3 tools/configure_emulator.py --target-host backend
```

Вторая команда заменяет архив искусственным live-планом, связывает терминал с автобусом и настраивает отправку эмулятора в `backend:9201`. Откройте [эмулятор](http://127.0.0.1:18080/) и дашборд: должны обновляться координаты и счётчик NDTP, а в запросе/ответе прогноза — стоять `execution: ml_http` и `method: learned`.

Начальное отклонение `+180 с` в этом примере задано для проверки интеграции, оно не приходит из NDTP. Подсказка действует пять минут; повторная команда начинает пример заново. Случайное движение эмулятора не проверяет качество GPS-детектора или модели. Настройка настоящего плана описана в [контракте входных данных](OPERATIONS.md#входные-данные).

Вернуться к архиву: `python3 tools/start_solution.py --no-build`. Чтобы запустить пустой live без архива: `python3 tools/start_solution.py --live --no-build`.

## 4. Открыть API, документацию и метрики

| Что | Адрес |
|---|---|
| Backend Swagger | http://127.0.0.1:8000/docs |
| ML Swagger | http://127.0.0.1:8001/docs |
| PyDoc и OpenAPI | http://127.0.0.1:8080/documentation/ |
| Состояние системы | http://127.0.0.1:8000/api/v1/state |
| Метрики обработки | http://127.0.0.1:8000/api/v1/metrics |
| Загруженная модель | http://127.0.0.1:8001/model |
| Журнал предупреждений | http://127.0.0.1:8000/api/v1/incidents/export |

В метриках есть число сообщений, ошибки, длина очереди, время HTTP-инференса и цикла обработки. Значения p95 относятся к последним 200 измерениям; это не MAE модели и не задержка от отправителя до отрисовки.

PyDoc и схемы API также лежат в [`docs/reference/`](reference/). Их можно читать без запущенного ML: откройте `docs/index.html` из локальной копии репозитория.

## Если что-то не запустилось

- Помощник сообщает об отсутствии файла — проверьте, что клонирован весь репозиторий с `dataset/`, и выполните `python3 tools/download_model.py` для весов. При явном `--data-dir` проверьте указанный путь.
- Docker сообщает `bind source path does not exist`, хотя папка существует — разрешите доступ к каталогу модели и датасета в настройках Docker Desktop или `mounts` профиля Colima, затем перезапустите Docker/Colima.
- Порт занят — остановите предыдущую копию системы. Две копии с одинаковыми портами одновременно не работают.
- Карта есть, но прогноза нет — проверьте статус автобуса и нажмите **Продолжить**. При пропуске GPS, неизвестном отклонении или отсутствии цели прогноз намеренно недоступен.
- Подложка не загрузилась — проверьте доступ к тайлам OpenStreetMap. Приём данных и прогнозы от подложки не зависят.
- Логи: `docker compose logs --tail=100 backend ml dashboard`. Для Colima используйте `docker --context colima-mos-transport compose ...`.

Остановить систему: `docker compose down --remove-orphans`. Датасет и скачанные веса останутся на диске.
