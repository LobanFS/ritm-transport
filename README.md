# Ритм

Система прогнозирует отклонение автобуса от расписания на остановке в горизонте 10–15 минут. Диспетчер видит положение транспорта, ожидаемое прибытие, риск задержки и предупреждения.

Три модуля работают в отдельных Docker-контейнерах:

- **Backend** принимает NDTP или воспроизводит CSV, сопоставляет GPS с остановками и вызывает модель.
- **ML-сервис** использует Transformer для истории отклонений и HGBR для итогового прогноза.
- **Дашборд** показывает карту, карточки автобусов и журнал предупреждений.

## Запуск

Нужны Docker с Compose v2 и Python 3.10+. Python нужен только для команд запуска; ML-зависимости устанавливаются внутри контейнеров. При первой сборке требуется интернет.

```bash
git clone https://github.com/LobanFS/ritm-transport.git
cd ritm-transport
python3 tools/download_model.py
python3 tools/start_solution.py
```

CSV для train и validate уже находятся в `dataset/`: скачивать или копировать их отдельно не нужно. Готовая модель скачивается из релиза и проверяется по SHA-256; обучение для запуска не требуется. Официальный образ эмулятора нужен только для отдельной проверки NDTP и в репозиторий не включён.

Откройте **http://127.0.0.1:8080** и нажмите **«Продолжить»**. Архив загружается на паузе и проигрывается до конца данных. В train доступны 39 автобусов; часть появляется позже выбранного времени старта. Это состав архива: ограничения на число автобусов в системе нет. Список на карте можно свернуть; выбор автобуса выделяет остальных на той же линии.

Свой исторический поток можно загрузить в интерфейсе: **Параметры → Свой архив CSV**. Форма доступна и из живого режима. Нужны телеметрия и план; `points.csv` с готовым текущим отклонением необязателен. [Порядок загрузки](docs/JURY.md#свой-архив).

На Mac с Colima добавьте `--context ИМЯ_КОНТЕКСТА` к команде запуска. Для этого проекта локально использовался `colima-mos-transport`.

Дополнительные режимы:

```bash
# Живой NDTP-поток: после запуска загрузите план и подключите источник.
python3 tools/start_solution.py --live
# Упрощённый экран диспетчера; архив начинает проигрываться сразу.
python3 tools/start_solution.py --ui-mode dispatcher
# Другой набор из репозитория.
python3 tools/start_solution.py --dataset-split validate
```

Порты: дашборд **8080**, Backend **8000**, ML **8001**, NDTP/TCP **9201**. Они должны быть свободны. По умолчанию доступ ограничен локальным компьютером. Остановка: `docker compose down` (для Colima: `docker --context ИМЯ_КОНТЕКСТА compose down`).

## Как читать результат

Прогноз — разность фактического и планового прибытия, в секундах. Цель выбирается по плановому времени в окне `(T+10, T+15]` минут. Будущие факты расписания не используются при инференсе.

Для расчёта нужны свежий GPS, известное текущее отклонение и подходящая цель. В API отсутствующий численный прогноз остаётся `null`. В train вероятность помечена «приближённо»: это перенос исторического калибратора, качество которого на смешанных реальных и синтетических данных отдельно не проверено. Причина внутри карточки автобуса объединяет наблюдения и полезные факторы модели; медленное движение само по себе не доказывает пробку.

## Что проверено

741 Python-тест, 79 проверок интерфейса и 13 проверок дорожной геометрии; запуск Docker с train и validate, официальный NDTP-эмулятор, Swagger и PyDoc. В коротком нагрузочном прогоне: 40 автобусов, 40 сообщений/с, принято 960 из 960 сообщений. p95 от отправки NDTP до ответа API дашборда — **1,62 с**, p95 HTTP-инференса — **333 мс**. Docker: ARM64, 4 vCPU, около 6 ГБ RAM. Проверены повторное подключение NDTP, отбрасывание дублей и повреждённых пакетов, резервный расчёт и восстановление после остановки ML. Отрисовка браузера и точность модели в этом прогоне не измерялись. [Результаты проверки](docs/verification.json).

Карта использует локальный кэш дорожных сегментов, подготовленный Ириной через OSRM по остановкам; для остальных перегонов сохраняется схема. Геометрия влияет только на отображение.

Дополнительно реализованы распознавание посещений по GPS, объяснение факторов модели, журнал предупреждений, отдельный режим диспетчера, накопление подтверждённых прибытий и запуск нескольких ML-реплик.

What-if в карточке задерживающегося автобуса предлагает подачу ближайшего подходящего автобуса с другой линии и показывает возможный выигрыш на целевой остановке. Это условный сценарий: время подачи рассчитывается по расстоянию, а возможность снять автобус с исходной линии подтверждает диспетчер. Прогноз модели и действующие планы не меняются. [Проверка сценария и допущения](docs/JURY.md#what-if-усилить-линию).
